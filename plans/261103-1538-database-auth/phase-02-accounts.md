# Phase 2 — Accounts and login

- **Create `backend/api/auth_schemas.py`.** Define SignupRequest, LoginRequest, PublicUser and TokenResponse. Reject extra fields. Signup usernames are trimmed and lowercased, 3–32 ASCII letters, digits, underscores or hyphens. Display names are trimmed, 1–80 characters. Signup passwords are 15–128 characters and preserved exactly. Login normalizes with the existing function and supports existing account names and passwords within explicit request size bounds.
- **Create `backend/src/services/auth.py`.** Add signup and login operations. Use Argon2id via a maintained dependency in `pyproject.toml` and update the lock. Verify existing hash formats before rollout. If no representative legacy hashes exist, report that limitation. Perform password work off the async event loop when using async routes. Use a dummy hash for unknown usernames.
- **Create `backend/src/storage/auth.py`.** Query normalized usernames, create employee accounts and insert sessions. Let the database uniqueness constraint settle concurrent signup. Map only the username uniqueness violation to 409. Use a transaction for login session issuance and guard account eligibility against concurrent disablement.
- **Create `backend/api/auth.py` and register in `backend/app.py`.** Validate inputs and origin, delegate to auth service, serialize public fields, and set refresh cookie on login. Set no-store on token responses. Do not log passwords or tokens.
- **First failing tests.** Create `backend/tests/test_auth.py` for signup payload and role, normalized duplicates, unknown and inactive users, generic 401 and successful token issuance. Prove concurrent duplicate signup yields one account in PostgreSQL. Check that stored credentials and session tokens are represented by hashes or digests.
