## Key insights

- `assigned_to` is NOT NULL and the status check has no `draft`; a migration is required.
- Autogenerate does not compare check constraints. Put the status and
  draft/assignee checks in a hand-written revision (per `AGENTS.md`).
- `MigrationRevisionTest` compares ORM and migrated schema; change both together.
- Library files are soft-deleted only; `FileBlobStore.path(key)` still resolves the bytes.
- `ACCOUNT_ELIGIBLE` (`backend/src/storage/auth.py:29`) already defines an active account.

## Requirements

Functional:
- Create a draft from a conversation the user owns (title + context, optional file IDs).
- List the user's inquiries: `box=sent` (own, including drafts) and `box=assigned`
  (assigned to the user, never drafts).
- Read one inquiry with context, attached files and events.
- Edit or soft-delete only the requester's own draft.
- Attach or detach library files while the inquiry is a draft. Attaching requires
  that the requester can read the file now (owner, not deleted).
- `GET /v1/experts` returns `{id, display_name}` of eligible experts.
  <!-- Updated: Validation Session 1 - eligibility is role expert only -->
  Eligible means active, not deleted and role `expert`. Admin accounts are not
  listed and are rejected at submit. Update the `Inquiry` docstring in
  `backend/src/storage/orm/inquiries.py` and `database-schema.md` §9, which
  currently say "expert or admin".
- Submit: requester only, status `draft`, eligible `assigned_to`, valid context.
- Download an attached file as requester or assignee, also after the file was
  deleted from the library.

Non-functional:
- Unrelated users, missing IDs and deleted inquiries all return the same `404`.
- No endpoint in this phase calls the agent.
- `context` is validated by a Pydantic model; unknown keys are rejected.

## Architecture

Migration (two revisions):
1. Autogenerated: `assigned_to` nullable; add `submitted_at timestamptz NULL`.
2. Hand-written: replace `ck_inquiries_status_allowed` to include `draft`; add
   `ck_inquiries_draft_or_assigned` = `status = 'draft' OR assigned_to IS NOT NULL`;
   change the `status` server default to `draft`.

Context snapshot (stored in `inquiries.context`):

```python
class EvidenceItem(BaseModel):
    """Evidence copied into the inquiry so it never depends on chat history."""

    model_config = ConfigDict(extra="forbid")
    kind: Literal["citation", "file"]
    title: str = Field(max_length=300)
    excerpt: str | None = Field(default=None, max_length=4000)
    location: str | None = Field(default=None, max_length=300)
    evidence_id: str | None = None  # citation evidence ID
    file_id: UUID | None = None     # must also exist in inquiry_files


class InquiryContext(BaseModel):
    """Situation, observations, attempted actions, proposed fix and evidence."""

    model_config = ConfigDict(extra="forbid")
    situation: str = Field(default="", max_length=4000)
    observations: str = Field(default="", max_length=4000)
    attempted_actions: str = Field(default="", max_length=4000)
    proposed_fix: str = Field(default="", max_length=4000)
    evidence: list[EvidenceItem] = Field(default_factory=list, max_length=50)
```

Submit requires non-empty `title` and `situation`; other fields may be empty.

Layering:
- `backend/src/storage/inquiries.py` — `InquiryStore` (queries, `app_transaction`).
- `backend/src/services/inquiries.py` — `InquiryService` (access rule, validation,
  submit, evidence lookup). Raises `InquiryNotFound`, `InvalidTransition`,
  `IneligibleAssignee`, `InvalidContext`.
- `backend/api/inquiries.py` — routers `/v1/inquiries` and `/v1/experts`.

Endpoints:

| Method and path | Who | Success |
|---|---|---|
| `POST /v1/inquiries` `{conversation_id, title, context, file_ids?}` | conversation owner | `201` inquiry (status `draft`) |
| `GET /v1/inquiries?box=sent\|assigned` | any user | `200 {inquiries: [summary]}`, newest first, limit 200 |
| `GET /v1/inquiries/{id}` | requester; assignee if not draft | `200` inquiry with `files`, `events` |
| `PATCH /v1/inquiries/{id}` `{title?, context?}` | requester, draft only | `200` |
| `DELETE /v1/inquiries/{id}` | requester, draft only | `204` soft delete |
| `PUT /v1/inquiries/{id}/files/{file_id}` | requester, draft only | `204` |
| `DELETE /v1/inquiries/{id}/files/{file_id}` | requester, draft only | `204` |
| `POST /v1/inquiries/{id}/submit` `{assigned_to}` | requester, draft only | `200`, status `open` |
| `GET /v1/inquiries/{id}/files/{file_id}/content` | requester or assignee | `200` bytes |
| `GET /v1/experts` | any user | `200 {experts: [{id, display_name}]}` |

Errors: `404` not visible; `409 invalid_transition` wrong status; `422`
`ineligible_assignee` / invalid context / unreadable file; `503` database unavailable.

## Success criteria

- Tests prove: owner creates, lists, reads, edits, deletes a draft; a non-owner
  gets `404` for each; a draft is invisible in the would-be assignee's box.
- `GET /v1/experts` excludes employees, admins, inactive and deleted accounts. Submitting
  to any of those returns `422 ineligible_assignee`; submitting to a listed expert succeeds.
- After submit, PATCH/DELETE/attach return `409`.
- Requester and assignee download an attached file after the owner deletes it
  from the library; an unrelated user gets `404`.
- Deleting the source conversation leaves the inquiry readable.

## Risk assessment

- Changing the status default can break code that inserts inquiries with raw SQL
  (`backend/tests/test_conversations.py:248`). Update that test to pass `status`
  and `assigned_to` explicitly.
- A file may be attached to a draft and then deleted from the library before
  submit. Accept this: the inquiry keeps the reference and the bytes remain.

## Security considerations

- Every query is scoped by requester or assignee; IDs alone grant nothing.
- `storage_key` is never returned. Downloads use `Content-Disposition: attachment`,
  `nosniff`, `Cache-Control: private, no-store`.
- Assignee eligibility is rechecked at submit, because roles can change.
