## Repositories

Create `backend/src/storage/repositories/`. Each repository takes an
`async_sessionmaker`, owns its transactions and raises one storage error type that
the API maps to 503, as `storage/auth.py` does with `AuthStorageUnavailable`.

| Module | Responsibility | Replaces |
|---|---|---|
| `knowledge_bases.py` | List active KBs, count created KBs, create, resolve name → ID | `kb_registry.py`, `databases.py` admin |
| `sources.py` | Create file + source in one transaction; get, list page with chunk counts, update status/text/metadata | `DocumentUploadStore` metadata, `raw_conversations` methods |
| `chunks.py` | Insert chunks with links and embeddings; get by IDs/source; review; scope update; similar/lexical/hybrid search | `knowledge_items` methods, `DocumentStore` writes/reads |
| `ingestion_jobs.py` | Enqueue with `pg_notify`, claim `FOR UPDATE SKIP LOCKED`, heartbeat, complete + next stage, fail/retry, recover stale, latest per source | `job_queue.py` |
| `extraction_runs.py` | Start/finish runs, active-content lookup, run history per source, overlap candidates | `extraction_runs.py` |
| `content_signatures.py` | Save bands (`put`); list sources with runs but no signature of a version (`unsigned`). Band matching is `ExtractionRunRepository.overlap_candidates`, as it needs the live run. | signature queries in `extraction_runs.py` |
| `knowledge_conflicts.py` | Save verdicts, current rows per pair, list for review, append review entries | `knowledge_conflicts.py` |

Keep pure helpers where they are and reuse them: `content_sha256`,
`extraction_fingerprint`, `shingles`/`signature`/`overlap`, `lexical_or_query`,
`rrf_fuse`, `build_knowledge_filter`.

Illustrative boundary. The record model stays the service contract; the repository
maps it to rows.

```python
class ChunkRepository:
    """Store and search knowledge chunks of one application database."""

    async def add_records(
        self, knowledge_base_id: UUID, source_id: UUID,
        records: Sequence[KnowledgeRecord], references: list[dict[str, Any]],
    ) -> None:
        """Insert records with embeddings and their source link in one transaction.

        Raises:
            ChunkStorageError: The database is unreachable or rejects the rows.
        """
        async with self._sessions.begin() as session:
            session.add_all(chunk_row(knowledge_base_id, record) for record in records)
            await session.flush()
            session.add_all(
                KnowledgeChunkSource(chunk_id=record.id, source_id=source_id, references=references)
                for record in records
            )
```

## First failing tests

- `backend/tests/test_app_knowledge_repositories.py` (integration, `TEST_DATABASE_URL`,
  reusing the disposable-database harness of `test_database_migrations.py`):
  - Creating a KB with a used name raises the conflict error; soft-deleted names stay taken.
  - Creating an upload source writes `files` and `knowledge_sources` together, or neither.
  - A chunk and a source in different KBs cannot be linked (database trigger).
  - Two enqueues for one source: the second raises the job-conflict error.
  - Two concurrent claims receive different jobs; completing a job creates its next
    stage in the same transaction; a stale job is requeued, then failed after
    `max_attempts`.
  - An active run blocks a second run with the same content, mode and fingerprint in
    the same KB, but not in another KB.
  - Conflict rows enforce `a_id < b_id`; review entries append without replacing history.
- Port the behavior cases of `test_job_queue.py`, `test_extraction_runs.py` and
  `test_knowledge_conflicts.py` to the new repositories rather than rewriting them.
